# ADR：Blog 实时报表数据契约

- 日期：2026-06-30
- 状态：Proposed

## 背景

报告 #19 原先通过 Spark 生成 JSON 快照，并由独立 HTML 页面轮询展示。统一
Blog 已支持对单个图表块启用实时刷新，因此继续维护独立页面会形成重复入口，
也会让报表文案、查询和演示流程不一致。

## 决策

保留 `lb_realtime_window_metrics` 作为完整窗口明细表，新增
`lb_realtime_blog_metrics` 作为 Blog 公开表。Spark 每个有效 micro-batch 在
同一 MySQL 事务中更新明细和公开表；公开表只保留最近处理的 12 个事件窗口，
包含 PV、收藏、加购、购买和数值化异常等级。

报告 #19 的图表块设置 `is_realtime=1`，由 Blog 每 1 秒重新查询公开表。删除
独立实时 HTML、JSON 快照和 Python 静态页面服务。

## 备选方案

1. 继续使用 JSON 和独立页面：实现已存在，但与统一 Blog 重复，部署入口更多。
2. Blog 直接查询完整明细表：无需公开表，但历史窗口会持续增长，页面排序与
   行数不稳定。
3. 只展示最新单窗口：查询简单，但无法直观看到趋势和预警跳变。

## 影响

- 优点：统一展示入口，固定 12 行查询规模，演示趋势更直观。
- 代价：每个有效 micro-batch 会重建一张 12 行公开表。
- 兼容性：完整窗口表不变；旧独立页面不再可用。
- 安全性：数据库凭据仍只通过环境变量或受保护凭据文件注入，不进入仓库。

## 部署与回滚

使用 `docs/luckyanjun_blog_report_issue19_realtime.sql` 只更新 `bindex=19`。
回滚时恢复旧报告 #19 查询，并回退本次提交；`lb_realtime_blog_metrics` 可保留，
因为它不影响原明细表和离线报告。
